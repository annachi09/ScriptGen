Query page against the tables listed below, or ask Claude to do it. The FK map was pulled from
`sys.foreign_keys` / `sys.foreign_key_columns` (real declared constraints, not guessed from naming).

## 5. Notes for future query design

- **Business keys vs surrogate IDs**: several tables have a human-readable business key alongside
  the numeric PK — `GCCOM_SECTOR_SUPPLY.NISS`, `GCCOM_CONTRACTED_SERVICE.NISC`,
  `GCCOM_PAYMENT_FORM.REFERENCE`, `GCCOM_SERVICE_REQUEST.SR_CODE`. The analyst usually starts from
  one of these and walks the FK chain inward.
- **Lookup tables** (`*_STATUS`, `*_TYPE`, `GCCOM_BILLING_TYPE`, `GCCOM_CONSUM_TYPE`,
  `GCCOM_AUTHORIZATION_STATUS`) are all keyed on `COD_DEVELOP` and carry a human label in
  `NAME_TYPE` or `DESCRIPTION` — join these in whenever a status/type code needs a plain-language
  label instead of just the code.
- **Self-referencing tables**: `GCCOM_AUTHORIZATION` (parent/child auth), `GCCOM_BILL` (ID_REG_BILL,
  regularization bills), `GCCOM_CONTRACTED_SERVICE` (primary/related contract), `GCCOM_ITEMS_TO_BILL`
  (ID_REPLACED_ITEM_TO_BILL), `GCGT_RE_READING` (ID_LAST_READING), `GCGT_RE_MEASUREMENT_POINT`
  (ID_MAIN_MP), `GCCOM_SERVICE_REQUEST` (LINKED_SERVREQ / ID_SERVREQ_TRANSFER).
- **This is a scoped subset.** ~224 more tables matched the original reading/billing keyword filter
  but haven't been drilled into at column level — ask for a specific table name and it'll be added
  here with verified FKs the same way.
- Existing app code already encodes two of these schemas as constants: `ADMIN_SCHEMA = "OUC_ADMIN"`
  and `READING_SCHEMA = "OUC_COMMON_ADMIN"` in `app/core/date_anomaly.py`.
